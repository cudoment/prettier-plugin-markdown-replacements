# prettier-plugin-markdown-replacements

[![CI](https://github.com/cudoment/prettier-plugin-markdown-replacements/actions/workflows/ci.yml/badge.svg)](https://github.com/cudoment/prettier-plugin-markdown-replacements/actions/workflows/ci.yml) [![npm](https://img.shields.io/npm/v/prettier-plugin-markdown-replacements.svg?logo=npm&logoColor=white)](https://www.npmjs.com/package/prettier-plugin-markdown-replacements) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE) [![Prettier 3.5+](https://img.shields.io/badge/prettier-3.5%2B-1A2B34?logo=prettier&logoColor=F7B93E)](https://prettier.io) [![Node.js 18+](https://img.shields.io/badge/node-%3E%3D18-5FA04E?logo=node.js&logoColor=white)](https://nodejs.org)

[English](./README.md) | **한국어**

등록해 둔 치환 규칙을 Markdown과 MDX 문서에 적용하고, 인라인 코드와 코드 블록과 MDX 주석은 원문 그대로 두는 [Prettier](https://prettier.io) 플러그인입니다.

자주 틀리는 표기나 프로젝트에서 통일하기로 정한 표기를 등록해 두면, 문서를 포맷할 때마다 함께 보정합니다.

## 요구 사항

| 항목     | 버전       |
| -------- | ---------- |
| Node.js  | 18 이상    |
| Prettier | 3.5.3 이상 |

## 설치

Prettier와 함께 개발 의존성으로 설치합니다.

```sh
# npm
npm install --save-dev prettier prettier-plugin-markdown-replacements

# yarn
yarn add --dev prettier prettier-plugin-markdown-replacements

# pnpm
pnpm add --save-dev prettier prettier-plugin-markdown-replacements
```

이 패키지는 ES 모듈이므로 `require()`로 불러오는 대신 `plugins`에 이름을 적어 등록합니다. Prettier 3의 플러그인 로더는 어떤 형식의 설정 파일에서든 ES 모듈을 직접 처리합니다.

## 설정

`plugins`에 패키지를 추가하고 규칙을 나열합니다. 기본값이 비어 있으므로 규칙을 등록하지 않으면 아무것도 치환하지 않습니다.

```json
{
  "plugins": ["prettier-plugin-markdown-replacements"],
  "markdownReplacements": ["어플리케이션=>애플리케이션", "메세지=>메시지"]
}
```

**적용 전**

<!-- prettier-ignore -->
```md
어플리케이션에서 메세지를 발송합니다.

| 필드 | 설명 |
| --- | --- |
| `메세지` | 메세지 상태 |
```

**적용 후**

<!-- prettier-ignore -->
```md
애플리케이션에서 메시지를 발송합니다.

| 필드 | 설명 |
| --- | --- |
| `메세지` | 메시지 상태 |
```

본문과 제목, 목록, 표 셀의 문장을 모두 보정하지만, 코드 표기로 감싼 값은 원문대로 유지합니다.

## 규칙 형식

| 형식   | 예시                             | 동작                                                               |
| ------ | -------------------------------- | ------------------------------------------------------------------ |
| 문자열 | `메세지=>메시지`                 | 문자열을 그대로 비교하고, 등장하는 모든 위치를 바꿉니다            |
| 정규식 | `/최대 ([0-9]+)개/g=>최대: $1개` | `/패턴/플래그` 형식으로 쓰고, `$1` 같은 캡처 참조를 쓸 수 있습니다 |

위 정규식을 등록하면 `최대 50개`가 `최대: 50개`로 치환됩니다. `g` 플래그는 생략해도 자동으로 적용되므로, 등장하는 모든 위치가 치환됩니다.

- 구분자는 문자열 형식에서는 처음 나오는 `=>`, 정규식 형식에서는 플래그 뒤의 `=>`입니다. 바꿀 문자열에는 `=>`가 들어갈 수 있습니다.
- 앞뒤 공백을 다듬지 않으므로 공백까지 규칙에 포함됩니다.
- 여러 규칙은 배열 순서대로 이어서 적용됩니다. 앞 규칙의 결과가 뒤 규칙의 입력이 됩니다.
- 구분자가 없는 항목이나 좌변이 빈 항목은 무시하고, 나머지 규칙은 그대로 적용합니다.
- `/`로 시작하지만 패턴이 잘못되었거나 플래그를 알 수 없어서 정규식 규칙으로 읽히지 않는 항목은 문자열 규칙으로 처리합니다. 그래서 `/docs/guide=>/docs/tutorial`처럼 경로를 치환하는 규칙도 정상적으로 동작하지만, 잘못 입력한 정규식은 오류를 내지 않고 아무것도 치환하지 않게 됩니다.
- 플래그는 실행 중인 JavaScript 엔진이 받아들이는 것을 그대로 쓸 수 있습니다. `v` 플래그는 Node.js 20 이상이 필요하며, Node.js 18에서는 이 플래그를 쓴 규칙이 문자열 규칙으로 읽힙니다.
- JSON 설정 파일에서는 패턴 안의 백슬래시를 두 번씩 적어야 합니다. JSON 자체가 백슬래시를 이스케이프 문자로 사용하기 때문입니다. 규칙 `/<br\s*\/?>/gi=><br />`는 설정 파일에 `"/<br\\s*\\/?>/gi=><br />"`로 저장합니다.

## 포맷할 때 치환하는 이유

Prettier는 문서를 어떻게 출력할지 정하는 도구이며, 문서가 무엇을 말하는지는 바꾸지 않습니다. 치환은 내용을 바꾸는 작업이므로, 이 동작을 Prettier 플러그인에 담은 것은 실수가 아니라 의도적인 선택입니다. 그래서 그 이유를 밝혀 둘 필요가 있습니다.

포맷은 모든 문서에 이미 적용되고 있는 유일한 단계입니다. 에디터에서는 저장할 때마다 실행되고, CI에서는 커밋마다 실행됩니다. 치환을 별도의 단계로 분리하면 그 단계를 실행하는 명령과 대상 파일을 찾는 규칙과 제외 규칙을 따로 관리해야 하며, 그 단계를 빠져나간 표기는 누군가 발견할 때까지 저장소에 남습니다. 규칙을 여기에 등록해 두면 프로젝트에서 통일하기로 정한 표기가 문서를 포맷하는 시점에 함께 적용되므로, 포맷된 문서는 보정까지 끝난 문서가 됩니다.

이 문서의 나머지 내용은 모두 그 선택에서 따라 나옵니다. 규칙은 원문 전체를 한 번에 보기 때문에, 줄바꿈을 넘나드는 규칙은 문서의 구조까지 바꿉니다. 그리고 원문을 그대로 유지해야 하는 구간은 어떤 규칙보다 먼저 들어냅니다. 규칙이 문서를 망가뜨릴 만큼 넓다고 판단되면 플러그인은 문서를 원문 그대로 남깁니다.

## 보호하는 구간

치환은 문서를 파싱하기 전에 원문에 적용되며, 다음 구간은 먼저 들어내고 치환이 끝난 뒤 원문 그대로 되돌립니다.

| 구간               | 예시                                 |
| ------------------ | ------------------------------------ |
| 인라인 코드        | `` `메세지` ``                       |
| 펜스 코드 블록     | ` ```js ... ``` ` 및 `~~~js ... ~~~` |
| 들여쓰기 코드 블록 | 공백 네 칸이나 탭으로 들여쓴 블록    |
| MDX 주석           | `{/* ... */}`                        |

API가 실제로 반환하는 값처럼 원문을 유지해야 하는 문자열은 코드 표기로 감싸 두면 보호됩니다.

펜스 코드 블록은 목록 항목 안을 포함해 어떤 깊이에 있더라도 인식하며, 앞에 빈 줄이 있든 목록 표식 바로 아래에 붙어 있든 마찬가지입니다. 반면 들여쓰기 코드 블록은 최상위에 있는 것만 인식합니다. 목록 항목이나 인용 블록 안에서는 공백 네 칸이 코드가 아니라 일반 내용을 뜻하는데, 이 플러그인은 블록의 중첩 관계를 추적하지 않습니다. 그래서 목록의 내용을 코드로 오인하여 그 안의 치환을 조용히 건너뛰는 위험을 감수하는 대신, 그런 구간은 보호하지 않고 그대로 둡니다. 다른 블록 안에 넣는 코드는 펜스로 감싸 주십시오. 닫히지 않은 펜스는 문서의 나머지 전체를 보호하는데, 이는 CommonMark의 해석과 Prettier의 출력을 따른 것입니다. 정보 문자열이 `md`처럼 마크다운 계열 언어를 가리키는 펜스는 Prettier가 같은 파서로 내장 문서처럼 다시 포맷하는데, 그 안에도 규칙은 적용되지 않습니다.

여기에 안전장치가 하나 더 있습니다. 보호 구간을 표시하는 내부 토큰까지 삼킬 만큼 넓은 패턴은 그 토큰을 문서에 흘리게 되므로, 그런 경우에는 문서를 손대지 않고 원문 그대로 둡니다. 그래서 `/[A-Za-z_]+/g=>X` 같은 규칙은 문서를 망가뜨리는 대신 아무 일도 하지 않습니다.

## 공백을 넘나드는 규칙 쓰기

치환은 문단 단위가 아니라 문서 전체를 한 번에 봅니다. 그리고 마크다운에서 줄바꿈은 구조를 나타냅니다. 줄바꿈을 넘나드는 패턴은 표기를 고치는 것이 아니라 구조를 바꾸는 셈이며, 두 가지 방식으로 문서를 망가뜨립니다.

| 패턴                                                     | 무너지는 것                                                                                                   |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `/\s*<br\s*\/?>\s*/gi`                                   | `\s`가 두 문단 사이의 빈 줄까지 잡아서 문단이 합쳐집니다                                                      |
| `/[^\S\r\n]*<br\s*\/?>[^\S\r\n]*(?:\r?\n(?![\r\n]))?/gi` | 흡수하는 줄바꿈 하나가 목록 항목 사이의 줄바꿈이기도 해서, 항목마다 `<br />`로 끝나는 목록이 한 줄로 뭉칩니다 |

가로 공백만 잡고 줄바꿈은 전부 그대로 두어야 합니다.

<!-- prettier-ignore -->
```
/[^\S\r\n]*<br\s*\/?>[^\S\r\n]*/gi=><br />
```

`[^\S\r\n]`은 줄바꿈이 아닌 공백을 뜻합니다. 문단 안의 줄바꿈은 Prettier에 맡기게 되며, `proseWrap: "never"`에서는 공백 한 칸으로 합쳐집니다. 그래서 `첫 줄 <br>` 다음 줄에 `둘째 줄`이 있으면 `첫 줄<br /> 둘째 줄`로 출력됩니다.

## 활용 예

### 줄바꿈 태그 통일하기

<!-- prettier-ignore -->
```json
{
  "markdownReplacements": ["/<br\\s*\\/?>/gi=><br />"]
}
```

`<br>`, `<br/>`, `<BR>`, `<br >`가 모두 `<br />`로 바뀝니다. 태그 앞뒤의 공백까지 정리하려면 위 절에서 설명한 공백 인식 형태를 씁니다.

### 이스케이프된 대괄호 되돌리기

Prettier는 문장 앞머리의 `[`가 링크로 읽히지 않도록 `\[`로 이스케이프합니다. 대괄호를 그대로 두고 싶은 프로젝트는 문자열 규칙 하나를 등록하면 됩니다.

<!-- prettier-ignore -->
```json
{
  "markdownReplacements": ["\\[=>["]
}
```

`\[앱] > \[일반]`이 `[앱] > [일반]`으로 출력됩니다. 코드 표기와 MDX 주석 안의 대괄호는 이스케이프를 유지합니다.

## 다른 플러그인과 함께 쓰기

Prettier는 한 언어에 파서를 하나만 씁니다. 이 플러그인도 파서를 제공하고, Prettier의 마크다운 프린터를 감싸는 플러그인도 파서를 제공하므로, **이 플러그인을 마지막에 두고** 다른 플러그인을 앞에 두어야 합니다. 앞에 두면 규칙이 조용히 무시됩니다.

```json
{
  "plugins": ["prettier-plugin-markdown-compact-tables", "prettier-plugin-markdown-replacements"],
  "markdownReplacements": ["어플리케이션=>애플리케이션"]
}
```

[`prettier-plugin-markdown-compact-tables`](https://github.com/cudoment/prettier-plugin-markdown-compact-tables)는 마크다운 표를 정렬 패딩 없이 출력합니다. 두 플러그인은 서로 독립적이어서 각각 단독으로도 동작하며, 위 순서로 등록하면 함께 동작합니다.

## 옵션

| 옵션                   | 타입       | 기본값 | 설명                                                                                                                                        |
| ---------------------- | ---------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `markdownReplacements` | `string[]` | `[]`   | 코드 스팬, 코드 블록, MDX 주석 밖의 텍스트에 적용할 치환 규칙입니다. `"from=>to"`는 문자열 규칙, `"/pattern/flags=>to"`는 정규식 규칙입니다 |

명령줄에서도 지정할 수 있습니다. 규칙이 여럿이면 플래그를 반복해서 적습니다.

```sh
npx prettier --write "**/*.md" --markdown-replacements "메세지=>메시지" --markdown-replacements "어플리케이션=>애플리케이션"
```

## 호환성

| Prettier      | 상태                                                                       |
| ------------- | -------------------------------------------------------------------------- |
| 3.5.3 ~ 3.9.x | 지원합니다. 3.5.3, 3.6.2, 3.7.0, 3.8.1, 3.9.6에서 테스트가 모두 통과합니다 |

파서는 Prettier의 내장 마크다운 플러그인이 선언하는 `markdown`, `mdx`, `remark`를 모두 지원합니다. 이 플러그인은 각 파서에 `preprocess` 단계를 추가하는데, Prettier의 내장 마크다운 파서에는 원래 이 단계가 없습니다. 프린터는 건드리지 않으므로 프린터를 감싸는 플러그인과 나란히 쓸 수 있습니다.

버전에 따라 달라지는 동작이 하나 있으니 알아 두시는 편이 좋습니다. MDX 주석의 내용은 지원하는 모든 버전에서 보호되지만, `{/* ... */}`라는 표기 자체는 `markdown` 파서에서 Prettier 3.9 이상에서만 유지되고 그 이전 버전은 강조 표기로 바꿔 버립니다. 그 표기가 있어야 해당 텍스트가 주석이므로, 이전 버전으로 그런 문서를 두 번 포맷하면 두 번째 포맷에서 주석의 내용까지 치환됩니다. MDX 주석이 있는 문서에는 `mdx` 파서를 사용하십시오. `mdx` 파서에서는 모든 버전에서 표기가 유지됩니다.

## 개발

```sh
# 의존성을 설치합니다
npm install

# 테스트를 한 번 실행합니다
npm run test:run

# 파일을 감시하면서 테스트를 실행합니다
npm test

# 테스트를 한 번 실행하고 커버리지를 보고합니다
npm run test:coverage

# 이 저장소의 파일을 포맷하거나, 포맷 상태를 검사합니다
npm run format
npm run format:check
```

테스트는 [Vitest](https://vitest.dev)로 작성되어 있으며 `__tests__/`에 있습니다. `index.js`의 커버리지는 문장, 분기, 함수, 줄 모두 100%로 유지하므로, 새 코드 경로를 추가하면 그 경로를 거치는 문서도 함께 추가해야 합니다.
